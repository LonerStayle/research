# 대화 메모리 요약기법 평가 (한국어 기준)

4개 에이전트 하네스의 **대화 메모리/컴팩션 요약 기법**을 동일 조건(동일 모델·동일 한국어 대화)에서 비교 평가한다.

## 평가 대상 하네스

| key | 레포 | 기법 소스 |
|---|---|---|
| `codex` | ~/jinsup_space/codex | OpenAI Codex CLI — compact/요약 프롬프트 |
| `claude-code` | ~/jinsup_space/CC | Claude Code — auto-compact 8섹션 요약 + 메모리 회상 파이프라인 |
| `grok` | ~/jinsup_space/grok-build | xAI grok-build — 메모리 레시피 |
| `openclaw` | ~/jinsup_space/openclaw | OpenClaw — memory flush / 메모리 전략 |

## 평가 설계

**핵심 질문**: 한국어 위주의 실제 에이전트 대화를 각 기법의 *원문 프롬프트 그대로* 압축했을 때, 압축본만으로 원 대화의 정보를 얼마나 회상할 수 있는가?

### 파이프라인 (대화 1건 × 기법 4종)

```
원본 대화 (한국어, ~/.claude/projects 실세션)
   │
   ├─ [1] 프로브 생성: 전체 대화를 읽고 QA 프로브 12개 생성 (정답 포함) → probes/
   │
   ├─ [2] 압축: 기법별 원문 프롬프트로 대화 요약 (모델 동일 → 순수 기법 비교) → runs/<tech>/
   │
   ├─ [3] 답변: 압축본"만" 보고 프로브 12개에 답변 (원본 접근 금지)
   │
   └─ [4] 채점: 블라인드 저지가 정답 대비 채점 (기법명 비공개, 0 / 0.5 / 1)
```

### 프로브 카테고리 (대화당 12개)

- **사실/결정** (4): 대화에서 내린 결정, 확정된 사실
- **기술 디테일** (4): 파일 경로, 함수/설정값, 에러 원인 등
- **사용자 의도/선호** (2): 사용자가 밝힌 취향, 지시, 제약
- **미결/다음 단계** (2): 남은 작업, 약속된 후속 조치

### 지표

1. **회상 정확도** — 프로브 채점 평균 (주지표, 카테고리별 분해)
2. **압축률** — 압축본 문자수 / 원본 문자수
3. **한국어 충실도** — 압축본이 한국어 고유 정보(고유명사, 한국어 용어, 뉘앙스)를 보존하는가 + 요약 언어 자체가 무엇인가
4. **효율 점수** — 회상 정확도 대비 압축률 (적게 쓰고 많이 기억할수록 우수)

### 공정성 통제

- 압축·답변·채점 전부 **동일 모델** → 차이는 프롬프트(기법)에서만 발생
- 압축 프롬프트는 각 레포 소스에서 **원문 그대로(verbatim)** 추출, 의역 금지
- 답변 에이전트는 원본 대화 접근 금지, 저지는 기법명 비공개(블라인드)

## 결과

두 라운드로 측정했다. **라운드 1**(10만 자·컴팩션 1회)은 천장 효과로 변별이 안 됐고, **라운드 2**(75만 자·컴팩션 11회)에서 점수가 벌어졌다. 단 아래 두 라운드 모두 **순위를 하네스 서열로 읽으면 안 된다** — 적대적 검토 결과 상당 부분이 실험 설계의 산물임이 확인됐다([report_r2.md 신뢰도 경고](results/report_r2.md) · 실무 시사점 [DESIGN 문서](DESIGN-chat-service-memory.md)).

> ⚠️ **핵심 편향 3가지**: ① 증분 체인 프로토콜이 openclaw 네이티브 동작과 동일(홈그라운드) ② "요약본만 읽기" 조건이 claude-code(원본복구)·grok(검색)의 회복 채널을 삭제 → 낮은 점수는 "회상력"이 아니라 "채널 제거 후 잔존율" ③ 프로브가 라운드 간 재편(R1↔R2 비교 무효). 표본 n=1·반복 0회.

### 라운드 2 — 800K 실전 스케일 + 11회 반복 컴팩션

이 조건에서 openclaw가 회상·효율 모두 앞섰다(회상 0.614·압축 3.8%·효율 16.2). **단 claude-code 0.182는 "붕괴"가 아니라 아티팩트** — 실제 산출물은 디테일을 다른 라운드 파일로 오프로드하는 포인터를 14개 남겼는데(정상 설계) 이 실험이 그 포인터를 못 읽게 막은 결과다. 상세 [`results/report_r2.md`](results/report_r2.md) · 시각화 [`results/report_r2.html`](results/report_r2.html)

| 기법 | 회상 | 압축률 | 효율 | 초반 | 후반 | 요약 언어 |
|---|---|---|---|---|---|---|
| openclaw | 0.614 | 3.8% | 16.2 | 0.375 | 0.750 | ko |
| codex | 0.568 | 7.0% | 8.1 | 0.375 | 0.833 | ko |
| grok | 0.295 | 2.5% | 12.0 | 0.062 | 0.667 | ko |
| claude-code | 0.182 | 3.5% | 5.2 | 0.000 | 0.583 | ko |

관찰(조건부): 이 무회복 조건에서는 반복 컴팩션 시 초반 정보 생존이 기법을 가른다. 데이터 `data2/`·`probes2/`·`runs2/`(44 압축본)·`results/r2_scores.json`.

## 폴더 구조

```
memory/
├── README.md            ← 이 문서
├── techniques/          ← 기법별 정리(<key>.md) + 원문 프롬프트(<key>-prompt.md)
├── data/                ← 선별·정규화된 한국어 대화 (conv-XX.txt + meta.json)
├── probes/              ← 대화별 QA 프로브 (conv-XX.json)
├── runs/<tech>/         ← 기법별 압축 산출물 (conv-XX.md)
└── results/             ← 답변/채점 원본, scores.json, report.md/html
```
