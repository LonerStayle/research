## Ⅲ. 두 플래그의 독립 축 — 조합 3종

```
SR ⭕ + isMeta ⭕  "하네스의 방송"        목록·알림·규칙 — 참고용, 주변과 무관
SR ⭕ + isMeta ✗  "포장된 유저 육성"      미드턴 끼어들기 — 출처는 표시, 화면엔 보임
SR ✗ + isMeta ⭕  "숨은 정식 입력"        스킬 본문·이미지 — 화면엔 안 보이지만 따르고/소비할 것
```

- **system-reminder** = 출처 라벨 ("이건 발화가 아니라 시스템 정보") — 모델에게 신뢰 등급을 알려주고, 사람 눈에선 지워짐
- **isMeta** = UI 숨김 플래그 — 트랜스크립트 표시 여부만 결정

`SR ✗ + isMeta ✗`는 그냥 일반 대화(유저가 친 프롬프트, 모델 응답)라서 표에서 제외. 이 두 비트의 조합이 클로드코드가 컨텍스트에 흘려 넣는 모든 텍스트의 신분증인 셈입니다.

## ② 선포장 = "보내는 사람이 집에서 미리 싸서 우체통에 넣음"

Stop 훅 차단 에러가 이 케이스인데, 코드를 보면:

```ts
enqueuePendingNotification({
  value: wrapInSystemReminder("Stop hook blocking error..."),  // ← 큐에 넣기 전에 이미 포장!
  ...
})
```

큐(우체통)에 들어가는 순간 **이미 포장돼 있습니다.** 나중에 큐가 드레인되면서 배달될 뿐, 포장 기계(렌더러)는 이걸 다시 싸지 않아요. "미리(先) 포장해서 보냈다" = 선포장.

## ③ 직조립 = "그 자리에서 싸서 그 자리에서 바로 끼움"

큐도 안 거치고 파이프라인도 안 거칩니다. 사이드 질문 코드가 **자기 자리에서 직접** 포장 문자열을 만들어 대화에 끼워요:

const wrappedQuestion = `<system-reminder>This is a side question...`  // 직접 조립

## 어태치먼트 밖 2개 채널 정리

**채널 A — 유령 재인쇄 (매 호출)**: `prependUserContext`가 스트리밍 호출부 안에 있어서(query.ts:655) 사이클 2든 50이든 **호출마다** 0번에 다시 찍힙니다. 다만 내용이 동결이라 "새 정보"는 아니고, 존재만 반복되는 SR이에요.

**채널 B — tool_result 인라인 (★ 이게 ReAct 전용)**: tool_result라는 그릇 자체가 **도구를 실행하는 사이클 안에서만 생기니까**, 이 채널은 턴 시작·유휴 상태에는 존재할 수 없습니다. 파일 하나 읽을 때마다 멀웨어 지침이 결과 꼬리에 따라붙고, 빈 파일이면 경고가 본문을 대체하는 식 — **도구 결과에 기생하는 SR**이라 수집 지점도 큐도 안 거칩니다. 어태치먼트 파이프라인과 완전히 무관한, 사이클 한정 배관이에요.

## 층위 2의 확장 — Swarm / Team (멀티 워커 협업)

코디네이터 모드는 혼자가 아니라 **swarm 인프라**와 물려 있습니다. `INTERNAL_WORKER_TOOLS` (coordinatorMode.ts:31)에 워커 전용 도구들이 있어요:
- **TeamCreate / TeamDelete** — 워커 팀 구성·해체
- **SendMessage** — 워커 간 메시지 (swarm inter-agent communication, `constants/xml.ts`의 `teammate-message` 태그)
- **SyntheticOutput** — 워커 산출물 합성
- `utils/swarm/inProcessRunner.ts` — 인프로세스 다중 에이전트 실행기

즉 **코디네이터(수퍼바이저) 1 + 워커 N** 구조로, 워커끼리도 서로 메시지를 주고받는 진짜 멀티에이전트 오케스트레이션입니다.

| 형태 | 상태 | 성격 |
|---|---|---|

## 워커는 일반 서브에이전트와 완전히 같은 경로

"worker"는 특별한 하네스가 아니라 **그냥 `subagent_type: "worker"`인 서브에이전트**예요. `runAgent.ts`에는 `isCoordinatorMode` 분기가 아예 없습니다 (위 grep에서 runAgent.ts는 worker/coordinator 키워드가 tool pool 주석 2줄뿐). 즉 워커 스폰은 Explore·Plan 스폰과 토씨 하나 다르지 않은 `runAgent` 경로를 탑니다.
