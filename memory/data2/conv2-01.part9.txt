## 올드스쿨과 다른 포인트 3개 (이 프로젝트의 확장)

1. **`stop_reason`을 안 믿습니다** — `query.ts:549` 주석: "stop_reason === 'tool_use'는 신뢰할 수 없음 — 항상 올바르게 설정되지는 않습니다". 그래서 분기 기준이 stop_reason이 아니라 **content에서 tool_use 블록을 직접 필터**(:821, :953). 어제 제가 그린 교과서 뼈대(stop_reason 분기)보다 방어적이에요.

2. **병렬/직렬 자동 분할** — `runTools`가 `partitionToolCalls`로 tool_use 배치를 나눠서 **읽기전용(isConcurrencySafe) 배치는 병렬**, 쓰기는 직렬 실행 (`toolOrchestration.ts:26-40`). 올드스쿨의 "for문 순차 실행"의 업그레이드.

3. **도구 = 설명문+구현+권한+UI 패키지** — `tools/BashTool/`만 봐도 `prompt.ts`(LLM용), `BashTool.tsx`(실행), `bashPermissions.ts`/`bashSecurity.ts`(권한·검증), `UI.tsx`(렌더링)로 관심사가 파일 단위 분리. 도구 하나가 "함수 하나"가 아니라 **미니 모듈**입니다.

한 줄 요약: 올드스쿨 뼈대가 그대로 있되 — **계약은 `Tool.ts`, 설명문은 `tools/*/prompt.ts`, 루프는 `query.ts:305`, 실행은 `toolOrchestration→toolExecution`, 결과조립은 `messages.ts`** — 각 단계에 방어막(stop_reason 불신, 짝맞춤 보정, 병렬분할, 권한게이트)이 한 겹씩 더 붙은 형태입니다.


**넛지(nudge)** = 영어로 "팔꿈치로 슬쩍 찌르다"라는 뜻이에요. 행동경제학에서 유명해진 용어인데(리처드 탈러의 책 『Nudge』, 2008), 정의는:

> **강제하지 않고, 선택의 자유는 그대로 둔 채, 원하는 방향으로 슬쩍 유도하는 것**

교과서적 예시가 학교 급식소예요:

```
강제:  "샐러드 안 먹으면 밥 안 줌"           ← 규칙
넛지:  샐러드를 눈높이 맨 앞 칸에 배치       ← 집으라고 강요 안 했지만
                                              집을 확률이 올라감
```

|---|---|---|

제일 좋은 증거가 그 방치 리마인더 문구 자체예요 — *"This is just a **gentle reminder** - ignore if not applicable"* (부드러운 리마인더일 뿐, 해당 없으면 무시해라). **CC 개발자들이 자기네 문구가 넛지라고 스스로 선언**하고 있는 셈이라, 이 단어가 딱 맞습니다.
