> 실행: 2026-08-04 · 대화 6건(각 ~10만 자, 한글 비율 0.49~0.64) × 기법 4종 = 24셀 · 에이전트 78개 · 에러 0
> 방법: 각 하네스의 **원문 요약 프롬프트(verbatim)** 를 동일 모델로 시뮬레이션 → 압축본만 보고 QA 프로브 12개 답변 → 블라인드 채점

> ## ⚠️ 신뢰도 경고
> 1. **회상은 사실상 무승부다.** 4기법이 0.944~0.972에 밀집(천장 효과) — 1위와 4위 차이가 약 2문제. 순위를 우열로 읽지 말 것. 실질 변별은 압축 효율·언어·한국어 뉘앙스에서만.
> 2. **"요약본만" 조건 편향.** 답변 에이전트가 요약본 하나만 읽는 조건이라, claude-code(원본복구 transcriptPath)·grok(검색)의 핵심 회복 채널이 삭제됨. 이들 점수는 "회상력"이 아니라 "채널 제거 후 단일요약 잔존율". 자세한 편향 분석은 [report_r2.md 신뢰도 경고](report_r2.md) 참조.
> 3. **동일 모델 자기채점·표본 6대화** — 통계적 일반화는 약함.

## 핵심 발견

### 1. openclaw — 효율에서 앞섬 (회상은 무승부)

회상 정확도는 0.972로 명목상 1위지만 2위 claude-code(0.965)와 사실상 동률(천장 효과). **실질 우위는 압축 효율**이다 — 압축본이 원본의 **13.5%** 로 4기법 중 가장 작은데도 회상이 최상위권.
비결은 5섹션 고정 구조(`Decisions / Open TODOs / Constraints·Rules / Pending user asks / Exact identifiers`)가
"미래 세션이 실제로 필요한 정보"에 조준돼 있다는 점 — 미결다음·의도선호 만점.
또한 4기법 중 유일하게 프롬프트에 **"요약 본문은 대화의 주 언어로 작성"** 이 명시돼 있어
6건 전부 한국어 요약이 나왔다. 다국어 인지가 설계에 들어간 유일한 하네스.
유일한 감점: 식별자 우선 정책의 이면으로 서사적 사실·한국어 용어에서 미세 손실(사실결정 0.958, 용어 9.83/10).

### 2. claude-code — 정확도는 사지만 "압축"은 안 한다

회상 2위(0.965)지만 압축률 **0.567** — 산출물이 원본의 절반 크기다. 9섹션 요약이
"모든 사용자 메시지 전수 나열 + Next Step verbatim 인용"을 강제하는 설계 탓.
이것은 버그가 아니라 철학이다: Claude Code는 요약을 손실 압축이 아니라
**인덱스 + 원본 포인터(transcriptPath)** 로 취급하며, 실제 하네스에서는 압축 후에도
원본 트랜스크립트를 다시 Read할 수 있다. 다만 "압축본만 남는" 조건에서는 토큰 효율 꼴찌.
언어는 혼합(영어 골격 + 한국어 인용 보존)이 지배적.

### 3. codex — 426자 프롬프트의 가성비, 그러나 사용자 선호에 약함

프롬프트가 4기법 중 극단적으로 짧은데도(고정 스키마 없이 포함 항목 4개만 지정) 0.944.
"다른 LLM에게 인수인계" 프레임이 진행상황·다음 단계는 잘 챙기지만,
**의도선호 0.833으로 전 기법 최하** — 사용자가 밝힌 취향·지시의 뉘앙스가 가장 많이 유실된다.
6건 전부 영어 요약: 한국어 표현 자체('분신' 같은 비유)는 사라지고 식별자만 원형 보존된다.

### 4. grok — 방어 엔지니어링은 최강, 언어 일관성은 최약

recall 0.958로 준수하고 9섹션 풀 리플레이스 + verbatim 인용 요구 덕에 기술디테일에 강하다.
그러나 프롬프트에 언어 지시가 없어 요약 언어가 **영어 3 · 혼합 2 · 한국어 1**로 셀마다 흔들렸다 —
동일 사용자의 연속 세션에서 메모리 언어가 널뛴다는 뜻. 한국어 일관성 관점에서 가장 불안정.

### 5. 공통 관찰

- **환각 0건 / 24셀 288프로브** — "모름" 정책과 결합하면 4기법 모두 틀린 기억을 지어내지 않았다 ("모름" 답변도 단 2건).
- **요약이 영어여도 회상 정확도는 크게 안 깎인다** — 답변 단계에서 재번역이 가능하기 때문.
  실질 차이는 (a) 사람이 요약을 직접 읽을 때의 가독성, (b) 후속 세션 언어 일관성, (c) 한국어 뉘앙스 표현의 소실에서 발생한다.
- **모든 기법의 공통 약점은 '미결다음'** (openclaw 제외) — 요약은 과거를 잘 남기지만 미래를 덜 남긴다.

## 한계 (해석 시 주의)

1. **천장 효과**: 0.94~0.97로 밀집. 프로브가 "요약에 살아남을 만한" 핵심 정보 위주라 변별력이 낮다. 더 지엽적인 tail-detail 프로브면 격차가 벌어질 것.
2. **동일 모델 시뮬레이션**: 프롬프트(기법) 차이만 분리 측정한 것. 실제 하네스의 모델·런타임 차이는 미반영.
3. **회상 채널 미평가**: grok의 하이브리드 검색(vector+BM25), CC의 transcriptPath·attachment 복원, segment 아카이브 등 "압축본 밖" 복구 채널은 평가 범위 밖. 특히 CC는 이 채널을 전제로 설계된 기법이라 실전 성능은 여기 수치보다 유리할 수 있다.
4. **사전 플러시 1패스 근사**: claude-code/grok/openclaw의 증분 플러시를 컴팩션 시점 1회 실행으로 근사.
5. **표본**: 대화 6건 × 12프로브, 프로브 생성·채점 모두 동일 모델 계열(자기 채점 편향 가능).
